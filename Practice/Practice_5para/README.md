# Практика 1. Циклы vs NumPy

Переписывание обработки большого массива с циклов Python на NumPy: сравнение времени и читаемости (задачи 1–11).

## Запуск

```bash
pip install numpy
python Praktika_1.py
```

Код всех задач — в файле [`Praktika_1.py`](Praktika_1.py). Данные генерируются с фиксированным `seed = 42` (`np.random.default_rng(42)`), основной массив — 1 000 000 чисел `normal`.

## Методика замера

- Время меряется через `time.perf_counter()`.
- Каждый вариант запускается 3 раза (для долгих — 1–2), берётся **минимум**: он стабильнее среднего, потому что убирает влияние прогрева и случайных задержек.
- Оба способа работают на одних и тех же данных, а результаты сравниваются через `np.allclose` — «быстрее» не должно означать «неправильно».
- Ускорение = время цикла / время NumPy.

> Абсолютные числа зависят от компьютера и меняются от запуска к запуску; ниже — результаты одного прогона.

## Задача 1. Сумма массива

Цикл `for x in a: s += x` против `a.sum()`.

| n | Цикл, мс | NumPy, мс | Ускорение |
|--:|---------:|----------:|----------:|
| 10⁵ | 6.61 | 0.03 | 215× |
| 10⁶ | 65.83 | 0.94 | 70× |
| 10⁷ | 850.07 | 10.41 | 82× |

**Вывод.** Разница больше 10× видна уже при n = 10⁵. Цикл Python тратит время на каждый элемент (интерпретатор, создание объекта на каждом шаге), а NumPy проходит по памяти одним циклом на C. Ускорение не растёт бесконечно: на малых n мешают накладные расходы вызова, на очень больших — скорость памяти. `a.sum()` — одна строка, понятная сразу; цикл — четыре строки и счётчик.

## Задача 2. Среднее и стандартное отклонение

Цикл с суммой и суммой квадратов («в лоб») против `a.mean()`, `a.std()`.

- Время: 131.45 мс против 1.88 мс (**70×**).
- Разница результатов: 3.4·10⁻¹⁸ (среднее), 1.0·10⁻¹⁴ (std) — меньше `1e-12`.
- На данных со смещением 10⁹ (истинное std ≈ 1): цикл даёт `0.0`, NumPy — `1.001`.

**Вывод.** Формула «сумма квадратов минус квадрат среднего» вычитает два близких больших числа и теряет точность (катастрофическое сокращение). NumPy считает std в два прохода — сначала среднее, затем сумма квадратов отклонений от него — и суммирует попарно, поэтому устойчивее.

## Задача 3. y = sin(x) + x²

Цикл с `math.sin(x) + x*x` против `np.sin(a) + a**2`.

- Время: 150.61 мс против 12.80 мс (**12×**).
- Память: массив NumPy — 8 МБ; список Python — миллион отдельных объектов (не менее 32 Б на элемент).

**Вывод.** NumPy-версия короче (одна строка). В выражении `np.sin(a) + a**2` создаются три массива: `sin(a)`, `a**2` и их сумма — то есть два временных и один результат. Ускорение здесь меньше, чем в других задачах, потому что `sin` сама по себе дорогая операция.

## Задача 4. Условная замена (clipping)

Цикл с `if/elif` против `np.clip(a, 0, 1)`.

- Время: 84.46 мс против 1.09 мс (**78×**).
- Изменено элементов: 658 924 из 1 000 000.

**Вывод.** В цикле один `for` и два `if`; в NumPy — 0 циклов и 0 ветвлений, одна строка, а имя `np.clip` сразу говорит о том, что делается.

## Задача 5. Сумма по строкам матрицы (100 000 × 10)

Двойной цикл против `m.sum(axis=1)`.

- Время: 133.43 мс против 2.15 мс (**62×**).

**Вывод.** `m.sum(axis=1)` читается как «сумма по строкам», а цикл — как индексы и счётчики (`i`, `j`, `s`). NumPy-вариант проще поддерживать: меньше мест, где можно ошибиться в индексах или забыть обнулить `s`.

## Задача 6. Вычитание среднего по столбцам

Цикл (среднее по столбцу, затем вычитание) против `m - m.mean(axis=0)`.

- Время: 330.94 мс против 4.16 мс (**80×**).
- Средние столбцов после нормировки ≈ 8.6·10⁻¹⁷ (то есть 0) в обоих вариантах.

**Вывод.** NumPy — одна строка благодаря broadcasting (вектор средних формы `(10,)` растягивается на все строки). Цикл — 8 строк с индексами `[i, j]` и двумя проходами по столбцу.

## Задача 7. Максимум и его индекс

Цикл с запоминанием `max_val` и `max_idx` против `a.max()`, `a.argmax()`.

- Время: 76.17 мс против 0.56 мс (**136×**).
- Если первый элемент — `NaN`: цикл возвращает `nan`, `a.max()` — `nan`, а `np.nanmax` — `5.0072` (верное максимальное значение).

**Вывод.** Сравнения с `NaN` всегда дают `False`, поэтому цикл ведёт себя непредсказуемо: если `NaN` стоит первым — вернёт `nan`, если в середине — молча его пропустит. Функции с префиксом `nan` явно и документированно игнорируют пропуски: это защита от реальных данных, а не «фича ради фичи».

## Задача 8. Фильтрация по порогу

`[x for x in a if x > 0]` против `a[a > 0]`.

- Время: 65.81 мс против 6.43 мс (**10×**).
- Память: ndarray — 4 МБ (8 Б на элемент), список — около 20 МБ (около 40 Б на элемент: указатель + объект `np.float64`), то есть примерно **в 5 раз больше**.

**Вывод.** Результат цикла — список объектов Python, результат NumPy — компактный массив. Выигрыш по памяти даже важнее выигрыша по времени.

## Задача 9. Замена по маске (in-place)

Цикл `if a[i] < 0: a[i] = -a[i]` против `a[a < 0] *= -1`.

- Время: 140.61 мс против 13.19 мс (**11×**).
- Оба варианта изменяют исходный массив (проверено: `result is a`), результаты совпадают с `np.abs(a)`.

**Вывод.** In-place важен для больших данных: если массив занимает 8 ГБ, копия для результата потребует ещё 8 ГБ, и программе может не хватить памяти. Для максимальной экономии есть `np.abs(a, out=a)`, который вообще не выделяет новой памяти.

## Задача 10. Комбинированная маска

`[x for x in a if -1 < x < 1]` против `a[(a > -1) & (a < 1)]`.

- Время: 97.33 мс против 5.99 мс (**16×**).

**Вывод.** Запись `-1 < x < 1` в Python читается лучше, но для массивов она не работает: цепочка сравнений использует `and`, а он требует одно значение `True/False`. Оператор `&` имеет приоритет выше, чем `<` и `>`, поэтому `a > -1 & a < 1` разбирается как `a > (-1 & a) < 1` и даёт ошибку (`TypeError` на float-массиве). Скобки обязательны.

## Задача 11. Матрица евклидовых расстояний (1000×3 и 1000×3)

Двойной цикл против broadcasting `np.sqrt(((X[:, None, :] - Y[None, :, :])**2).sum(axis=2))` и против формулы через матричное умножение.

| Способ | Время, мс | Ускорение |
|--------|----------:|----------:|
| Двойной цикл | 1331 | — |
| Broadcasting | 33.9 | 39× |
| Через `X @ Y.T` | 4.6 | 290× |

- Временный массив `(1000, 1000, 3)` из `float64` занимает 1000·1000·3·8 Б = **24 МБ**.

**Вывод.** Broadcasting — самый короткий код, но он платит памятью: для 20 000 точек временный массив составил бы около 9.6 ГБ. Формула ‖x−y‖² = ‖x‖² + ‖y‖² − 2·x·y через `X @ Y.T` хранит только саму матрицу расстояний и работает быстрее; готовая функция `scipy.spatial.distance.cdist` делает то же без временных массивов. Компромисс: простота кода ↔ расход памяти.

## Общие выводы

1. NumPy быстрее циклов Python в 10–300 раз на больших массивах, потому что вычисления идут одним циклом на C по непрерывной памяти, а не через интерпретатор.
2. Код на NumPy короче и читается как описание операции («сумма по строкам», «обрезать до [0, 1]»), а не как последовательность индексов и счётчиков.
3. Выигрыш бывает не только по времени, но и по памяти (задача 8) и по устойчивости вычислений (задачи 2 и 7).
4. У векторизации есть цена: временные массивы (задачи 3 и 11) и особенности синтаксиса (скобки в масках, задача 10).
